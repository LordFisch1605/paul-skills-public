# Method log

Things learned while building profiles that the method did not already know.

**How to use this file:** append a dated entry in the session that produced it — the concrete
case first, the lesson second. Appending needs no permission. Promoting an entry into a rule in
`SKILL.md` does, because a rule there changes every future profile. One entry is a case; two
pointing the same way are a pattern worth proposing.

Worked examples are referenced by path only. Some profiles quote private material and must not be
copied into this repository.

---

## 18.08.2026 — Seeded from three existing profiles

Entries below are derived from profiles built before this skill existed. They are the evidence the
skill was written from, recorded here so the reasoning is not lost.

Sources:

- An academic German profile — the most developed of the three; carries three rounds of
  correction pairs and a documented status switch.
- An academic English profile — short, built without correction pairs.
- A personal-sincere German profile, local only.

### The threshold turned out to be real

The German academic profile crossed five correction pairs and its a-priori sections were demoted
to secondary. Two contradictions surfaced immediately: the pairs said the person *breaks*
sentences apart where the chat-derived section said they chain them, and they set roughly a third of
the dashes the a-priori section expected.

Lesson: inference from informal material gets sentence architecture wrong specifically. The
threshold exists because that is the section that needs overriding first.

### Ordering costs a full revision round

That same profile records a session that drafted a chapter *before* evaluating the newest
correction round, and had to redo it. The rule "read the pairs before drafting" is in the skill
because of that documented cost, not on principle.

### A third register needed its own file, not a section

The personal profile could not be a section inside the academic one: the academic file
deliberately excludes the warm first-person register, and its data-basis caveat ("sources are
informal, register does not transfer") is what created the gap.

Lesson: one file per register, cross-linked in section 1. A register the sibling profile
explicitly excludes is a signal that a separate profile is owed — not an omission to patch.

### The same trait can be an asset or ballast depending on register

Concessive movement, weighing, concrete numbers and honest self-analysis appear as traits to
*discipline* in the academic profile and traits to *expand* in the personal one. Identical
evidence, opposite verdicts.

Lesson: the "verdict" line per trait is not decoration. A trait copied between profiles without
re-deciding its verdict imports the wrong instruction.

### Private material forces a file-level lock, not a redaction pass

The personal profile quotes WhatsApp conversations including third parties. It carries a lock
notice and a `.gitignore` exclusion rather than being scrubbed, because scrubbing would have cost
the evidence that made it worth building.

Lesson: decide local-only at the start of intake. Retrofitting it after quotes are in the file
means either losing them or auditing every line.

### A material bank is worth adding for recurring output

The personal profile ends with pre-cleaned, reusable building blocks for the motivation the person
writes about repeatedly — already in the target register, freely combinable.

Not yet promoted to `SKILL.md`: one case. If a second profile for a recurring output type benefits
from the same, propose it as a standard optional section.
