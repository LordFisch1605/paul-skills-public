# The section skeleton of a voice profile

The canonical shape, in order. The ordering is load-bearing: a reader who stops after section 1
must already know which register applies, and a reader who stops after section 3 must already
know what not to do.

Section numbers are stable. New evidence gets appended as lettered sub-sections (`5a`, `5b`) so
that a reference to "section 3" stays valid a year later.

---

## Header block

Four things, in this order, before section 1:

1. **Lock notice**, if the file quotes private material. What it contains, that it is excluded
   from sync, and that it must not reach a remote.
2. **Purpose line.** "Reference for any AI model that drafts or checks *X* in the style of *N*."
   Name the concrete formats — "motivation letters and programme applications" beats "personal
   texts".
3. **Relation to sibling profiles**, if any exist. Give their paths and say what this file adds
   that they deliberately leave out. This is what stops a reader loading the wrong one.
4. **Data basis.** Word count, text type, time periods, audience. Then the sentence that governs
   everything below: all indented quotes are verbatim, typos included; anything beyond them is
   marked *extrapolation*.

## 1. The registers — decide first

A table, one column per register the person writes in, including the raw source register.

Rows that earn their place: which formats it governs · grammatical subject · tone · how "I" is
handled · surface markers allowed or forbidden (emoji, capitals, contractions) · which external
rulebook applies.

Then, as a callout: **the costliest mistake in choosing wrong**, with a worked example — one raw
sentence rendered into each register. If the person's natural habit collides with an external
rule, this is where it goes, with the collision named and resolved.

## 2. What carries over

One sub-section per trait, most distinctive first. Each one:

- **A name for the trait** that a drafting session can be told to apply.
- **The count**, where countable.
- **One or two verbatim quotes**, indented.
- **What it becomes** in the target register — the raw → target pair.
- **A verdict**: kept, kept and expanded, or kept but constrained.

Traits worth checking for, since they recur across people: concession before judgement · weighing
both sides before a verdict · causal self-analysis · concrete numbers instead of intensifiers ·
context before the request · how paragraphs open.

## 3. What is dropped

Same shape, opposite verdict. A table works when the drops are surface-level (emoji, capitals,
repeated letters), prose when a drop needs justifying.

Cover at least: hedges and softeners, with the ones cut outright named individually · stance
markers ("personally", "honestly") · sentence chaining · evasions into the generic ("one", "people")
· register-specific surface habits.

Close with a **do-not-overcorrect** callout. Dropping the source register's surface must not
produce stiff, over-nominalised prose — give a sentence that went one step too far, so the ceiling
is visible as well as the floor.

## 4. Recurring mechanical errors

Spelling, punctuation, agreement — whatever the material actually shows, with the correction. Not
a general style guide: only errors evidenced in *this* person's text, so a checker knows where to
look first.

## 5. A worked rewrite

One passage of raw material, rendered into the target register, with the changes named. Long
enough to show the traits interacting.

## 5a, 5b, … Correction pairs

Appended as they are harvested, one lettered sub-section per round, dated.

Each pair: **Pattern &lt;letter&gt; — one-line rule as a claim about the person.** Then the drafted
version, the person's version, and one line on what it implies.

Each round ends with:

- **Interventions that are *not* style rules** — fact corrections, scope changes, one-offs.
  Naming them stops the next session generalising them.
- **A count**: how many pairs from how many rounds, and what the next intake should be.

When the count crosses roughly five pairs, add a dated **status switch** — from here the pairs are
primary and the a-priori sections are secondary — and list the known contradictions between them
by section number.

## 6. Checklist

Ten to twelve imperative questions, in drafting order: register first, structure next, mechanics
last. End with the read-aloud test: *does it still sound like them?*

## 7. Limits and how the file closes them

State what the evidence base does **not** support — usually: one text type, one period, informal
source. Then the closing condition: what material would fix it, and what happens when it arrives.

Then the operating rule, which belongs here rather than in a process document because this is
where it gets read: **record corrections in the session they occur, and read the pairs before
drafting the next version.**
